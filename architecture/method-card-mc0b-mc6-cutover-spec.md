## 1. Purpose and normative convention

This document turns the accepted MC0A substrate into a staged, reviewable cutover contract. It does not change MethodCard content, create finding or phase authority, accept a ProgramFacts runtime, or accept a report runtime. It contains no implementation code.

Only rows carrying an `MCUT-*` identifier are normative. `MUST`, `MUST NOT`, `SHALL`, and `SHALL NOT` outside those rows are explanatory quotations or summaries and create no additional requirement. Each normative row cites its controlling sources. Where this profile selects one permissible cutover mechanism from several mechanisms allowed by an owning document, the source map labels that choice as a profile decision.

## 3. Accepted MC0A floor and residual

MC0A already pins the following semantics: per-card denominators are disjoint and card-owned; exact targets bind current source-file identity; missing target-source identity yields a lower bound, not exactness; stale graph, snapshot, catalog, method, or source binding fails; candidate/evidence relationships are many-to-many; candidate union parity is exact; producer and reviewer outputs are separate; the activated runtime cannot fall back to the legacy receipt; and the foundation grants no phase, finding, semantic, severity, negative, or report authority.

MC0A deliberately did not prove the principal that generated the caller-supplied expected graph/selector mapping. That residual is the first cutover gate, not an implementation detail.

## 4. Dependency order and authority flow

Every global dependency before work dispatch SHALL follow this fixed prefix; a field may bind only an item strictly to its left:

`OWN-v1 predecessor → Graph-v2/public-v3/OWN-v2 semantic contracts → accepted public-v3 and OWN-v2 pins/receipts → accepted MC0A and PhaseIO/WorkerTransaction/ArtifactLedger/backend substrate → closed schema files → executable-schema registry → schema-package manifest → artifact/work registry → governance profile → mode-resource profile → resource-boundary case set → deterministic resource-boundary result/receipt → independent resource-defaults review/acceptance → U-02-independent core profile → additive report-mapping definition → profile-local ownership binding → combined 97-row/98-instance requirement registry → denominator provider/source/basis → canonically ordered obligation locators/obligations → final denominator → runtime-input base candidate/attestation`.

After that prefix, the driver expands this same predecessor-only micro-DAG separately for every work identity `w`:

`w.semantic predecessor authorities/attestations/receipts → w staged-file-census candidate/attestation → w ControlPhaseIOInputSet → w WorkPlan candidate/attestation → w runtime-authorization candidate/attestation → w WorkerPhaseIOInputSet candidate/attestation → w AttemptArm → w semantic output candidate → w WorkerExecutionReceipt → w PhaseIO commit → w ArtifactLedger event → w artifact-attestation envelope`.

A work locator becomes eligible only when every declared predecessor locator has resolved to a `predecessor_work_id` with a terminal artifact attestation and every semantic predecessor binding required by that work kind exists. Among all eligible locators, the driver expands the lexicographically smallest lowercase `work_locator_id`; only after its census/control input exists is `work_unit_id` computed. Independent micro-DAGs may interleave only without reversing an edge. A reviewer work's semantic predecessor set contains the producer output attestation and producer execution receipt. A reconciliation work's set contains both producer and reviewer output attestations and both execution receipts. Any unresolved census, missing terminal predecessor, self/later edge, or nonempty graph with no eligible locator is `DEPENDENCY_CYCLE`; no WorkPlan is emitted. This repeated expansion is globally acyclic because a successor locator cannot enter the eligible set until every cross-work predecessor reaches the leftmost semantic-predecessor position of its own micro-DAG.

Stage-level successors consume completed micro-DAGs in this order: `evidence/application authorities → consumer activation candidate/attestation → independent activation authorization → enactment → MC4/MC5 acceptance → MC6 work micro-DAGs and policy/ledger/assurance → MC6 grader/blocking-review/acceptance → downstream report mapping instance/adoption → report P5A/P6/publication/final acceptance`. No node may bind a digest, ID, receipt, acceptance, or mapping instance to its right. In particular, each WorkPlan binds its predecessor runtime-input base and per-work control/census rather than its successor runtime authorization; resource-defaults acceptance binds no stage fixture denominator or stage grader; and MC6 binds only the MethodCard-owned report mapping definition, never downstream report adoption.

The fixed ProgramFacts semantic interface is Graph-v2 plus public-v3 plus OWN-v2. Its canonical public logical identities, in order, are `mechanical_program_facts.v3.json`, `mechanical_program_facts_receipt.v3.json`, and `mechanical_program_facts_debt.v3.json`, with schemas `plamen.mechanical_program_facts.v3`, `plamen.mechanical_program_facts_receipt.v3`, and `plamen.mechanical_program_facts_debt.v3`. MethodCard binds the active-generation PhaseIO/ArtifactLedger identities and digests; it does not rename, merge, or republish them. Only the final file pins and independent architecture/runtime receipts remain deferred in U-01.

### 5.2 Closed type dictionary

All fields are required. Absence is permitted only as explicit `null` for `Nullable<T>`. Every object is closed recursively (`additionalProperties:false`); every array fixes item type, uniqueness, order, and bounds; an unknown key, enum, union branch, schema ID, identity prefix, or nullable position is invalid. `Bool` is JSON `true` or `false`; `String` is 0 through 65,535 Unicode scalar values after NFC; `NonEmptyString` is `String` with one through 65,535 scalars; `Id` matches `[A-Za-z0-9][A-Za-z0-9._:/@-]{0,255}`; `Digest` is 64 lowercase hex characters; `UInt` is 0 through 9,223,372,036,854,775,807; `UInt32` is 0 through 4,294,967,295; `Path` is a nonempty project-relative POSIX path with no empty, dot, drive, UNC, or backslash segment; `ExternalPath` matches `[A-Z]:/(?:[^/\\]+/)*[^/\\]+` after NFC and forbids `.`/`..`, alternate streams, UNC, and backslash; `CanonicalFilePath` is exactly `Path|ExternalPath`; `JsonPointer` is RFC 6901 canonical syntax; `GitHubAnchor` matches the exact slug convention in Section 2. `Set<T>[m,n]` is a duplicate-free array of `m..n` values sorted by `CJ(value)` bytes; omitted bounds mean `[0,4294967295]`. `Seq<T>[m,n]` is an array of `m..n` values whose array index is the exact zero-based ordinal; when `T` has an `ordinal` field it must equal that index; omitted bounds mean `[0,4294967295]`. `NonEmptySet<T>` means `Set<T>[1,4294967295]`. A new field, prefix, cardinality, nullable position, or enum value requires a schema version.

In every exact schema declaration below, bare `schema` means a const equal to the displayed schema ID; bare `candidate_id`/`candidate_digest` mean `Id`/`Digest` under MCUT-015; bare `receipt_id`/`receipt_digest` mean the receipt equivalents; and bare count/digest names mean `UInt`/`Digest`. No other omitted type is permitted. Every schema has one entry in the schema-package manifest. If a row states a special prefix, that prefix is exact. Otherwise candidate prefix is `mc-candidate:<schema-tag>:` and receipt prefix is `mc-receipt:<schema-tag>:`, where `<schema-tag>` is the schema ID after removing leading `plamen.`, lowercasing ASCII, replacing each maximal non-alphanumeric run with one hyphen, and trimming hyphens. The suffix is the corresponding digest. Prefix selection is recorded in `SchemaPackageEntry` and cannot vary at runtime.

## 9. Honest application coverage and proposal parity

Coverage kind is either `EXACT` or `LOWER_BOUND`. Stale, malformed, or conflicted authority is invalid rather than a third coverage kind. `unknown_remainder` is a boolean paired with a non-empty reason and optional lower-bound count; it is not an estimated denominator.

For card `c`, let `D_c` be the frozen known obligation identity set and partition it into `APPLIED_c`, `MISSING_c`, `INVALID_c`, and `UNKNOWN_c`. Application completeness is true only when coverage is exact, unknown remainder is false, the partition is disjoint and has union `D_c`, and every member is `APPLIED`. An exact empty denominator is permitted only when the accepted upstream provider proves exact enumeration and exact zero.
