### 2.1 Normative canonical-JSON and scalar policy

`CJ(x)` means the exact UTF-8 bytes produced by RFC 8785 JSON Canonicalization
Scheme (JCS) over the already parsed JSON value `x`. Every parser must reject
duplicate object names, invalid UTF-8, lone surrogates, non-RFC-8259 extensions,
and non-finite numbers before schema validation. Every governed JSON artifact
must be serialized exactly as `CJ(record) || 0x0A`; a byte-different but
value-equivalent JSON serialization is `RECORD_NOT_JCS_CANONICAL`.

All schema-declared integers must arrive as raw JSON integer number tokens: no
fraction, exponent, negative zero, quoted alias, NaN, or infinity. They must be
finite, exactly representable, within `0..9007199254740991`, and within the
tighter schema bound. The sole counter scalar is deliberately a string and is
governed separately in section 6.3. Validators may not inherit permissive host
JSON, Base64, integer, datetime, or ordering behavior.

For every component object `X`, `component_sha256 = SHA256(CJ(X))`. The object
is obtained by duplicate-rejecting parse of its JSON fence, then canonicalized;
the Markdown fence's authored key order, whitespace, newline, and raw byte hash
are never a preimage or oracle. This rule applies identically to all eighteen
components inherited from r13 and the new conformance component in section 11,
for nineteen components total.
The candidate preimage is itself a closed JSON object and its digest is also
`SHA256(CJ(candidate_preimage))`.

### 6.3 Total Base64, monotonic-counter, and UTC semantics

`stdout_base64` and `stderr_base64` use the RFC 4648 standard alphabet with
mandatory correct padding and this complete grammar:

```text
^(?:[A-Za-z0-9+/]{4})*(?:[A-Za-z0-9+/]{2}==|[A-Za-z0-9+/]{3}=)?$
```

The empty string canonically represents zero bytes. Each encoded string is at
most 11,184,812 ASCII characters and decodes to at most 8,388,608 bytes.
Validation computes decoded length before allocation, uses a strict RFC 4648
decoder, rejects misplaced/excess padding and non-zero unused pad bits,
re-encodes with the standard alphabet and required padding, and requires exact
input equality. Decode failure, bound excess, size-field mismatch, or re-encode
mismatch rejects; permissive host-decoder repair is forbidden.

Every `monotonic_counter` is a JSON string of exactly twenty ASCII digits. It
decodes as unsigned base-10 only after the regex check and must be at most
`18446744073709551615`. Fixed width is the sole representation of each value,
including leading zeroes, so lexical and numeric order are identical. For each
capture, `start < end`. Across replay rows in exact index order:

```text
row[0].start < row[0].end < row[1].start < row[1].end < ...
  < row[8].start < row[8].end
```

Comparison is unsigned lexicographic comparison of two already validated
twenty-byte ASCII strings; no host integer conversion is required. Equal,
decreasing, malformed, wrong-type, or above-U64 counters reject.

`observed_utc` is a JSON string exactly `YYYY-MM-DDTHH:MM:SS.mmmZ`, with year
`0001..9999`, a valid proleptic-Gregorian calendar date, hour `00..23`, minute
and second `00..59`, and exactly three fractional digits. Leap seconds and
offset aliases reject. UTC remains non-authoritative metadata and is never used
to order events; canonical validation only makes its bytes total and bounded.

Replay rows are the exact ordered subject universe `6..14`. `uniqueItems` is a
schema floor, not the semantic oracle: row `i` has subject ordinal `6+i`, the
corresponding capture ordinal `15+i`, command sequence `i`, and exact
