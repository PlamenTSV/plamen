# Central negative-closure authority

Terminal negative effects are destructive state transitions. A verifier status,
model agreement, Markdown label, callback, or caller-supplied mapping is supporting
evidence only. Production consumers accept one loader-owned authority reconstructed
from current files by `scripts/closure_broker_v2.py`.

## Terminal families

| Effect | Sole terminal provider | Current production availability |
|---|---|---|
| `OUT_OF_SCOPE` | observed `MECHANICAL_SCOPE_EXCLUSION` completion | registration/replay implemented; requires a driver-owned provider launch |
| `ALIAS_TO_SURVIVOR` | validated applied semantic-dedup receipt chain | live deterministic adapter |
| `REFUTED_FULL` / `ZERO_HARM` | observed authenticated exhaustive-negative completion | registration/replay implemented; no production driver launcher yet |

The last row is deliberately not described as operational. The driver consumes a
valid authority if an observed provider completion was registered, but it does not
currently launch that provider. Normal audit runs therefore reopen exhaustive
negative proposals rather than terminally accepting them.

## Replay contract

Observed-provider bundles bind the exact candidate, claim manifest, source,
premise/domain denominator, evidence files, provider output, worker completion,
publish receipt, effective backend/model, and independent worker/reviewer
principals. `register_completed_negative_closure_provider` is the only supported
bundle creation path. It validates the completed execution before atomic publish.

Applied equivalence is adapted only from current, validated primary/supplemental
semantic-dedup receipts. The adapter replays the canonical output, accepted identity
delta, field-complete preservation, and live final survivor. Proposal Markdown is
never authority.

Missing, stale, tampered, incomplete, conflicting, or self-authored evidence yields
broker debt and a mandatory reopen/body/human-review result. Broker writes are
atomic and idempotent. A failed publish never grants authority.

## Consumer matrix

| Consumer | Terminal behavior |
|---|---|
| application skeptic | central `REFUTED_FULL` decision or additive reopen |
| candidate-negative skeptic | central `REFUTED_FULL` decision or additive reopen |
| inventory reconciliation | central full refutation or applied-equivalence decision; otherwise content-bearing debt |
| finding lifecycle | terminal negative decision must carry and replay the exact embedded central decision |
| report disposition | central full-refutation/zero-harm decision or BODY plus re-verification |
| compound verification/report binding | central full-refutation decision or human review |
| severity/R10 | no destructive negative transition: refuted premises retain upstream severity; R10 is an un-demotion floor |
| L1 composition | remains fail-open under its separate P1-L authority; central adapter deferred until that owner lands |

Positive confirmations are unchanged. The broker never deletes a positive finding,
manufactures proof, or lowers severity. Local v1/shadow authorities remain readable
for migration evidence but are never terminal.

## Known limitations

- There is no production exhaustive-negative provider launcher. Adding one requires
  a code-owned launch policy, neutral oracle, exact denominator construction, and
  WER completion registration; a model must not be allowed to self-issue a bundle.
- Mechanical scope registration has the same launch prerequisite. The broker
  validates the observed provider contract but does not infer scope from prose.
- Compound central APIs are live, but the generic compound substrate has no current
  production callsite outside its adapters; integration must pass the same central
  authority to evaluate, bind, and validate.
- L1 composition files are intentionally not modified by this cutover while the
  independent P1-L workstream owns them.

These are visible integration limits, not reasons to weaken the default. Until a
provider is available, the correct result is nonterminal support and renewed work.
