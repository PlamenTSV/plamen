## 0. The one principle, and the answer to "where is the golden area"

Every defect found today was a **recognizer narrower than the language its own
producers emit** — never the model underperforming, never a validator being
"too strict":

| defect | the proxy that was measured | the property that mattered |
|---|---|---|
| `\| CC ID \|` unrecognised (prior session) | one header spelling | any identity column |
| backticked `**Source IDs**: \`file:ID\`` bound to nothing | operational view with inline code blanked, regex ate the blanked span | the reference the producer wrote |

| redirect envelope indent | column-0 match | byte-exact envelope with the runtime's indent |
| field value swallowing `---` | "value runs to next bold field" | value ends at a thematic break |
| "restorable" row with empty source bytes | axis vocabulary | bytes exist to splice |
| my own degrade lane accepting `UNMATCHED` | the preservation marker string | can the aggregate actually restore this row |

So the golden area is not strict-vs-loose. **Gate on the property; never on a
representation of it. Identity, dedup binding, severity, disposition and
source-action authentication stay fail-closed.** `docs/design/gate-repair-
architecture.md` §1.1a/§1.1b/§1.2 is the binding statement; the LangSec rule
is the test: a recognizer must match the intended language exactly — no
broader, no narrower.
